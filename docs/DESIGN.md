# Решения Forma /02

## Аудит MVP

Сильные стороны: цельный источник в `Asset.source`, общий SVG-конвейер для холста/экспорта, отделённые модель и планировщик, контроль ID, переносимый JSON, S/L и тесты геометрии. Эти части сохранены.

Слабые стороны: равномерная сетка без связей между предметами, один результат, буквальный поиск, много вертикального места под техническими настройками, слабое различие выбранных состояний и отсутствие масштаба просмотра. Исправления направлены на эти причины, а не только на цвет кнопок.

Перед изменениями создан локальный Git-снимок: `efb3e2a`, тег `baseline-mvp-2026-11-02`. Его production-сборка сохранена локально в игнорируемой папке `.baseline-dist/` для сравнения. Исходные SVG не изменялись.

## Визуальная концепция

**Композиционный стол**: тёмная библиотека удерживает инструменты на периферии, светлая рабочая область показывает иллюстрацию, коралловый цвет обозначает действие и выбор. Цвета самих композиций задаются предоставленными палитрами и не связаны с акцентом интерфейса.

Фундамент:

| Роль                     | Решение                                                              |
| ------------------------ | -------------------------------------------------------------------- |
| Основной шрифт           | Segoe UI Variable / Segoe UI, системный fallback Arial               |
| Акцент пустого состояния | Georgia; применяется только к короткому вводному сообщению           |
| Числа и метаданные       | Consolas / monospace                                                 |
| UI-акцент                | Коралловый `#FF684B`                                                 |
| Инструментальная панель  | Графит `#212627`                                                     |
| Фон/поверхности          | Тёплые нейтральные оттенки; без стекла и декоративных свечений       |
| Сетка                    | Три колонки, высота рабочего окна, панели с независимым скроллом     |
| Контролы                 | Общие радиусы 4–6 px, тонкая граница, единая геометрия иконок Lucide |

Выделение отмечает целый объект. Размеры маркеров не зависят от масштаба холста. Для маленьких объектов минимальная невидимая область захвата — 22 экранных px; в экспорт она не попадает. Анимации ограничены короткими изменениями состояния/размера и отключаются при `prefers-reduced-motion`.

На мобильном экране сначала видны запрос, холст и варианты, затем компоненты и свойства. Это поддерживает основной сценарий, сохраняя ручное редактирование доступным ниже по странице.

## Почему компоновка стала содержательнее

Фокус меняет пространственный и послойный приоритет, но не увеличивает один предмет относительно остальных. Иерархию создают исходные размеры, роль, положение, цветовой контраст и порядок рисования.

Для знакомых семейств есть композиционные отношения: книга/папка может служить опорой телефону или небольшому предмету; лампа задаёт вертикальный противовес; мелкие объекты связывают группу. Сначала размещается опора и связанные с ней элементы, затем другие поддерживающие предметы. Для неизвестных пользовательских семейств используется предсказуемый набор относительных направлений.

Кандидаты позиций проверяются по пересечению повёрнутых bounding box. Если обычная пара перекрывается слишком сильно, следующий кандидат отодвигается или поворачивается вокруг опоры. Для осмысленных пар допускается большее наложение. После этого весь набор вписывается единым коэффициентом, а фоновым предметам разрешена ограниченная обрезка. В варианте для заголовка заранее исключается область текста.

Это не модель визуального вкуса и не оптимизация по реальной альфа-маске. Такой выбор даёт объяснимое, воспроизводимое поведение и сохраняет структуру исходников; ограничения viewBox-приближения указаны в README.

## Почему локальный словарь

Базовый сценарий должен работать без платного API. Шесть тем покрывают доступную иллюстративную библиотеку: знания, музыка, финансы, идеи, порядок, внимание. Устойчивые выражения и основы слов связывают тему с конкретными существующими `assetId` и фокусом.

Названия предметов имеют приоритет над тематическим набором. Простые отрицания исключают предмет; указание «на фоне» выбирает соответствующий исходник. Неизвестные слова не превращаются в новые рисунки. Объяснение открыто через интерфейс. Общее LLM-понимание не заявляется.

Контракт `CompositionPlanner` сохранён: будущий серверный адаптер может предлагать только ID, координаты, углы и общий масштаб. SVG-разметку и ключи в клиент передавать не требуется.

## Компромиссы

- Объекты нельзя масштабировать индивидуально ради более эффектного кадра: это нарушило бы задание. Фокус регулируется композицией.
- Контроль пересечений консервативен, потому что использует viewBox. Он надёжнее объясняется и тестируется, но иногда оставляет больше воздуха, чем дизайнер оставил бы вручную.
- Предпросмотры вариантов — настоящие SVG, не картинки. Это увеличивает количество SVG-узлов, зато пользователь выбирает тот же векторный результат, который затем экспортируется.
- Положение и история сцены отделены от масштаба просмотра. Увеличение холста не должно менять JSON или экспорт.

Технические инварианты, проверки и честные пределы перечислены в `../VALIDATION.md`.
